# Как это устроено

## Схема

```
OpenCode
   │  POST /v1/chat/completions   (OpenAI-формат + массив tools)
   ▼
src/server.mjs  ·  127.0.0.1:8787
   │  POST /api/v2/tools/llm_chat/execute   (model + systemPrompt + один строковый context)
   ▼
Sim Cloud  →  hosted-модель (Claude / GPT / Gemini / …)
```

Sim не умеет OpenAI-формат и не принимает `tools`, поэтому прокси делает две вещи: переводит формат сообщений и эмулирует вызов инструментов.

## Почему эмуляция

`llm_chat` принимает только `model`, `systemPrompt`, `context`, `temperature`, `maxTokens`. Ни `tools`, ни `tool_choice`, ни `response_format`. В исходниках Sim (`apps/sim/tools/llm/chat.ts`) это видно напрямую.

Блок Agent внутри воркфлоу тулы умеет, но они принадлежат Sim (интеграции, knowledge base, Function, свои JS-тулы) и исполняются на его стороне. Наружу их не отдать.

Итог: инструменты, которые должен исполнять OpenCode (чтение файлов, shell, patch), живут только в промпте.

## Цикл одного запроса

1. **Разбор.** Сообщения превращаются в плоский транскрипт с маркерами:
   ```
   [system] …   → уходит в systemPrompt
   [user] …
   [assistant]
   [tool call read #call_abc]
   {"path":"notes.txt"}
   [tool result read #call_abc]
   Read file notes.txt …
   ```
2. **Инъекция протокола.** В *конец* транскрипта (ближе к генерации, модели лучше слушаются) добавляется блок «TOOL CALLING PROTOCOL» со схемами тулов и примером.
3. **Вызов Sim.** Один запрос, температура 0.
4. **Разбор ответа.** Ищется JSON `{"tool_calls":[…]}`; если модель выдала XML `<invoke>`, он тоже разбирается.
5. **Починка.** Аргументы приводятся к типам схемы, лишние ключи выкидываются, обязательные подставляются.
6. **Дедуп.** Если такой же вызов уже есть в транскрипте с результатом — модели говорится «уже выполнено», вместо повторного круга.
7. **Свои тулы.** `now`/`web_fetch`/`web_search` исполняются внутри прокси, результат дописывается в контекст, запрос повторяется (до `maxProxyToolHops`).
8. **Ответ.** OpenCode получает либо `tool_calls`, либо текст в стандартном формате OpenAI.

## Свои тулы

| Тул | Что делает | Защита |
|---|---|---|
| `now` | текущее время, TZ, ISO | — |
| `web_fetch` | GET по http(s), HTML → текст | блок loopback и приватных IP, таймаут 20 с, лимит символов |
| `web_search` | DuckDuckGo HTML, топ-N результатов | — |

Они добавляются к тулам OpenCode и исполняются прокси, поэтому клиент их не видит и не тратит на них шаги.

## Кеш

Только для чата без тулов (иначе состояние меняется между шагами и кеш вреден). Ключ — SHA-1 от модели, системного промпта и транскрипта; TTL 10 минут, LRU на 200 записей. Хиты видны в `/stats`.

## Ограничения, заложенные в дизайн

- **Нет настоящего стриминга.** Sim отдаёт ответ целиком; SSE-чанки переигрываются после получения. Клиенту отправляются `: ping` каждые 10 с, чтобы соединение не считалось мёртвым.
- **Нет кеша промпта.** Каждый шаг заново отправляет весь контекст (~20k токенов системного промпта OpenCode).
- **Эмуляция хрупкая по природе.** Модель может пропустить тул, соврать «сделано» или сломать JSON. `nudge`, дедуп и починка аргументов снижают частоту, но не гарантируют результат.
- **Лимиты free-плана Sim:** 2 параллельных исполнения (отсюда семафор), 300 с на вызов, 1000 кредитов.

## Файлы

| Файл | Роль |
|---|---|
| `src/server.mjs` | HTTP-сервер, эмуляция, кеш, свои тулы, статистика |
| `src/cli.mjs` | мастер настройки, панель управления |
| `src/opencode.mjs` | установка/удаление провайдера в `opencode.json` |
| `config.json` | настройки (не коммитится) |
| `models.cache.json` | каталог моделей из Sim (обновляется раз в 12 ч) |
