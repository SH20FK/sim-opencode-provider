# sim-opencode-provider

OpenAI-совместимый прокси, который отдаёт **hosted-модели Sim** (Claude, GPT, Gemini, Grok, Kimi, GLM…) в **OpenCode** — нужен только ключ Sim, без ключей отдельных провайдеров.

У Sim нет OpenAI-эндпоинта `/v1/chat/completions`, а у инструмента `llm_chat` нет параметра `tools`. Прокси закрывает оба пробела: переводит формат OpenAI в API Sim и **эмулирует function calling**, чтобы агент OpenCode реально читал файлы, запускал команды и правил код этими моделями.

```
OpenCode ──/v1/chat/completions──▶ 127.0.0.1:8787 ──▶ Sim /api/v2/tools/llm_chat/execute
```

## Возможности

| Что | Детали |
|---|---|
| **Каталог моделей** | 88 hosted-моделей без своего ключа, тянутся из Sim (`?all=1` — все 288) |
| **OpenAI chat API** | `POST /v1/chat/completions`, `stream: true` (SSE), ответы с `tool_calls` |
| **Эмуляция тулов** | схемы тулов подставляются в конец транскрипта, ответ парсится обратно в `tool_calls` (JSON и XML `<invoke>`) |
| **Починка аргументов** | приведение типов, выкидывание лишних ключей, подстановка обязательных, дедуп |
| **Nudge** | сломанный вызов → автоматический переспрос (настраивается) |
| **Свои тулы** | `now`, `web_fetch` (HTML→текст, приватные IP блокируются), `web_search` (DuckDuckGo) — исполняет прокси |
| **Кеш ответов** | SHA-1 модель+промпт, TTL 10 мин, LRU (только чат без тулов) |
| **Fallback** | повтор на другую модель при `402/404/429/5xx` |
| **Keepalive** | SSE-пинг каждые 10 с, пока Sim думает |
| **Статистика** | `/stats`: запросы, вызовы тулов, токены, кеш-хиты, задержки по моделям |
| **Мастер + панель** | `setup.bat` / `manage.bat`: ключ, автопоиск воркспейса, порт, автозапуск, логи, тесты |
| **Без зависимостей** | только встроенные модули Node, один файл прокси |

## Требования

- Node.js **20+**
- Аккаунт Sim и API-ключ (`sk-sim-…`) — Settings → API keys на [sim.ai](https://www.sim.ai)

## Быстрый старт (Windows)

```bat
setup.bat     :: мастер: ключ -> воркспейс -> проверка модели -> порт -> автозапуск
manage.bat    :: панель: старт / стоп / статус / логи / настройки / тест
```

Дальше в OpenCode: `/models` → **Sim (free)** → модель.

## Быстрый старт (любая ОС)

```bash
cp config.example.json config.json   # вписать simApiKey и workspaceId
node server.mjs
```

Проверка:

```bash
curl http://127.0.0.1:8787/health
node tests/smoke.mjs
```

## Провайдер в OpenCode

`~/.config/opencode/opencode.json`:

```json
{
  "provider": {
    "sim": {
      "npm": "@ai-sdk/openai-compatible",
      "name": "Sim (free)",
      "options": {
        "baseURL": "http://127.0.0.1:8787/v1",
        "apiKey": "sim-local"
      },
      "models": {
        "claude-sonnet-5-5": {
          "name": "Claude Sonnet 5.5 (Sim)",
          "limit": { "context": 200000, "output": 32000 },
          "cost": { "input": 0, "output": 0 }
        }
      }
    }
  }
}
```

`apiKey` — заглушка, OpenCode требует поле, прокси его игнорирует. Настоящий ключ Sim лежит в `config.json`.

## Конфиг

`config.json` (в `.gitignore`, образец — `config.example.json`):

| Поле | По умолчанию | Смысл |
|---|---|---|
| `simApiKey` | — | ключ Sim (`sk-sim-…`) |
| `workspaceId` | — | ID воркспейса (мастер находит сам) |
| `workflowId` | `""` | необязательно, только для пункта «запустить воркфлоу» |
| `port` | `8787` | локальный порт (слушает только `127.0.0.1`) |
| `toolEmulation` | `true` | подставлять схемы тулов в промпт |
| `toolTemperature` | `0` | температура в режиме тулов (держит JSON строгим) |
| `maxConcurrent` | `2` | параллельные вызовы Sim (free-план — 2) |
| `requestTimeoutMs` | `290000` | таймаут одного вызова |
| `fallbackModel` | `""` | модель для повтора при ошибке |
| `cache.enabled` / `ttlMs` | `true` / `600000` | кеш ответов |
| `proxyTools.*` | `true` | встроенные тулы |
| `nudge.maxRetries` | `2` | переспросы при сломанном вызове |
| `maxProxyToolHops` | `3` | лимит внутренних раундов тулов |

## HTTP API

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | живость, число моделей, флаги |
| `GET` | `/stats` | счётчики и задержки по моделям |
| `GET` | `/v1/models` | ID hosted-моделей (`?all=1` — весь каталог) |
| `POST` | `/v1/chat/completions` | формат OpenAI, стриминг поддерживается |

## Ограничения

- **Эмуляция ≠ нативный function calling:** модель может пропустить тул, соврать «готово» или повторить вызов. Nudge/дедуп/починка снижают частоту, но не убирают.
- **Настоящего стриминга нет:** Sim отдаёт ответ целиком, SSE нарезается после.
- **Нет кеша промпта** на пути `llm_chat` — каждый шаг отправляет весь контекст заново.
- **Free-план:** 2 параллельных запуска, 300 с на вызов, 1000 кредитов (~1 кредит за запуск, hosted-модели по 0).
- **Неофициально:** если Sim включит биллинг тул-вызовов или уберёт hosted-модели, прокси начнёт отдавать `401/402`.

## Безопасность

- Слушает только `127.0.0.1`.
- `config.json` хранит ключ в открытом виде — не коммить (уже в `.gitignore`), не вставлять в issues.
- `web_fetch` блокирует loopback/приватные адреса, но это не песочница: URL от модели считай недоверенными.
